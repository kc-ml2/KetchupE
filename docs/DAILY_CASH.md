# 일일자금일보 Tool v1

사용자가 채팅에 **“일일자금일보 작성해줘”**라고 요청하면 기존 자연어 라우터가 `daily_cash`를 선택한다. 파일은 PC의 파일 선택 또는 연결된 업무 폴더에서 지정한다. 업로드하지 않는다. Tool은 Electron utility process에서 실행되고 확인 답변·원천 해시·버전·조회 환율은 실행 상태에 보관된다.

## 확정 규칙 (2026-10-15 담당자 확인)

- 작업일 10/15 → 일보 기준일 10/14(금일), 전일 10/13. KC 파일명 `261014_...xlsx`는 계좌잔고 마감일, 즉 일보 기준일이다(작업일 전날). 이름에 날짜가 없으면 확인한다.
- 일보 통합문서에서 기준일 직전 날짜 시트의 H열 금일금액을 새 날짜 시트의 D열 전일금액으로 이월한다. 최신 시트가 7일 넘게 떨어지면 중단한다. 주말 등 간격이 있으면 마지막 마감/무거래 기간을 확인한다.
- KC의 **O열 계좌잔고**를 금일금액으로 사용한다. **환종별합계 KRW의 O열**을 최종 **총 원화**와 비교한다. 고정된 52행 대신 헤더와 합계 표식으로 찾는다. 일보 쪽도 정기예금 행이 매일 늘고 줄어 49행 아래 구역(정기예금·신탁·집행내역·합계)은 라벨과 합계 수식으로 위치를 찾는다. M열 장부잔액으로 대체하지 않는다.
- 전일 금액 + 실제 증가 − 실제 감소 = 계좌잔고를 확인한다. 장부 입출금(J/L)과 O열이 맞지 않으면 담당자에게 실제 입출금 총액을 묻는다. 차액을 임의 지급/입금으로 계산하지 않는다.
- 정기예금은 원금·통화·은행·명시적 만기일로 연결한다. 동일 조건/원금 슬롯은 순서대로 연결하고 담당자가 연결표를 확인한다. 만기일 도래 시 전일 원금 전액을 감소 처리한다. KC 잔고가 남아 있으면 연장/미결제를 확인하도록 중지한다. 만기 이자와 입금 계좌를 만들어내지 않는다.
- 사업부문은 KC 계좌별 O열을 기존 일보의 O/P 보조표에 연결하여 합산한다. 계좌코드+통화를 키로 써 같은 외화 계좌의 USD/CNY를 구별한다. 병합 셀은 실제 master 값만 이어 읽는다.
- 주간계획의 `세부계획(원화,외화)`에서 C열(유입)/H열(유출)의 **지주현금**만 선택한다. B열 실제 날짜로 필터하고 합계 구간을 제외한다. 파일명의 날짜는 계획일로 쓰지 않는다. 동일 날짜가 두 파일에 있으면 버전 선택을 요구한다.
- 주요 집행내역: 왼쪽은 기준일 실적, 오른쪽은 작업일 계획. KC는 개별 거래 적요를 제공하지 않으므로 주간계획을 가져와 담당자가 실적·계획을 확인/수정한다. 금액 변경·미집행·추가 거래를 지원하고 실적 마감금액이 원화 현금 잔고와 같아야 한다.
- 하나은행 **일보 기준일 최종 고시**를 조회한다. JPY 100엔 고시를 1엔당 원화로 환산한다. 조회일·기준일·회차·고시일시·응답 해시를 남긴다. 휴무일 등 다른 날짜가 반환되면 그 날짜 적용을 확인하며 조회 실패 시 재조회를 묻고, 재조회도 실패하면 담당자가 하나은행 화면에서 확인한 매매기준율(USD·JPY 100엔·CNY)과 고시일·회차를 직접 입력한다. 수동 입력은 출처 "담당자 수동 입력"으로 검증 시트와 최종 확인 코드에 남으며, 추정 환율로 완료하지는 않는다.
- 금액은 Decimal 30자리 정밀도로 연산하고 원천 소수액을 유지한다. KC 계좌잔고는 원 단위 정수이고 일보는 이자 소수 원을 그대로 이월하므로 1원 미만 차이는 일치로 보고 금일금액에는 수식값(소수 포함)을 남긴다. 그 이상의 허용오차는 없다. Excel 셀/이미지 표시 서식이 원 단위여도 검증은 내부 값으로 한다.

## 입력과 확인

업무 폴더는 따로 없다. 왼쪽 "파일" 탭에서 검색 폴더를 등록하면 같은 폴더가 업무 폴더로도 등록되고(해제 시 함께 해제), 입력 카드의 "파일 선택…"으로 고른 파일도 업무 자료로 등록된다. 폴더를 등록해 두면 실행 시작 시 `suggest`가 파일명 규칙으로 입력을 미리 채운다. 작업일은 폴더 연결 여부와 상관없이 서울 기준 오늘이 기본값이며 첫 실행 전에는 바꿀 수 있다(첫 실행 후 확정). 전일 일보는 전일 일보는 `일일자금일보`를 포함하고 YYMMDD가 기준일 전날 이하인 최신 파일(샘플·업무흐름·테스트·검증 제외), 주간계획은 `주간자금계획` MMDD가 기준일·작업일 이하인 최신 파일(주 경계면 두 개), 자금현황표는 `기준일YYMMDD_`로 시작하는 파일이다. 담당자가 대화 안의 입력 카드에서 확인하거나 바꾼 뒤 실행한다.

최초 입력: `workDate`, `previousReport` 1개, `weeklyPlans` 1개 이상, `cashStatus` 1개(기준일 파일, 날짜가 작업일 전날과 다르면 중단). 원천을 바꾸려면 새 작업을 시작한다.

양식 인식과 계좌 연결은 코드에서 처리한다. 알려지지 않은 계좌는 `accountBindings`에 확인한 연결을 입력할 수 있지만 대상은 기존 양식의 허용 셀과 통화/예금 종류로 제한한다. 예금이 새로 생기거나 만기가 바뀌어 기존 전일 일보와 다르면 갱신된 전일 일보/업무 규칙이 필요하다. 사용자에게 임의 코드 실행을 허용하지 않는다.

주간계획 실적 확인은 입력 카드의 표(`movements` 필드)에서 한다. 계획 행마다 실제 금액을 고치고(0은 미집행) 계획에 없던 거래는 행을 추가한다. 표는 아래 수정 JSON으로 직렬화되어 도구에 전달되며, 번호는 최초로 제시된 계획 목록 기준이다. 적요/거래처 변경은 changes 항목의 `description`/`party`로 전달할 수 있다(표 UI에서는 금액만 수정).

```json
{
  "changes": [{ "index": 1, "amount": "12000" }, { "index": 2, "amount": "0" }],
  "add": [{ "direction": "out", "description": "추가 지급", "party": "거래처", "amount": "5000" }]
}
```

전일 수식의 저장 결과가 없으면 0으로 추정하지 않는다. 수식 없이 완전히 빈 셀(숨겨진 미사용 행의 장부금액 등)은 Excel 산술과 같이 0으로 읽는다. 빈 셀이 20개 이하면 셀별 숫자 입력란(`cell_H9` 등)으로 확인한 값을 입력하고, 그보다 많으면 계산값 없이 저장된 파일이므로 Excel에서 저장한 원본으로 새 작업을 시작한다. 전일 자료의 수식 캐시는 원천 값이지 자체 재계산 증거가 아니므로 최종 확인에 원본 재계산·저장 확인을 포함한다. 기타 받을어음/적금/신탁은 변동 없음 확인 후 이월한다. 이 부문의 변동 업무는 현재 v1 범위 밖이다.

최종 확인은 실제 적용 계좌·환율·계획 대비 차이·만기 목록의 해시 코드로 한다. 담당자는 코드를 타이핑하지 않고 카드의 확인 버튼을 누르며, 카드가 그 코드를 제출한다. 표를 바꾸면 새 코드로 다시 확인한다. 휴무일 이월·계획 없는 날짜·고시일 적용·환율 재조회 확인도 같은 버튼 방식이다. 확인 답변은 영구 계좌 매핑이나 다음 실행의 자동 승인으로 저장하지 않는다.

## 출력

원본은 수정하지 않고, 기존 통합문서에 `YYMMDD` 시트와 `검증_YYMMDD` 시트를 추가한 **새 XLSX 파일**을 만든다. 해당 날짜 시트가 있으면 덮어쓰지 않는다. 새로운 시트의 병합/열 너비/숨김/서식을 복제하고 금액·합계를 다시 계산한다. 기존 시트는 유지한다. 이전 양식의 CNY 합계에 JPY가 포함된 수식과 잔액 0의 환율 나눗셈 오류는 새 시트에서 수정한다.

PNG는 새 시트의 보이는 셀을 표 렌더러로 그린다. 폭은 값이 있는 마지막 열(사업부문 자금현황표(KC)의 O:P)까지, 높이는 그 보조표의 마지막 행까지 포함해 기안서에 붙여도 오른쪽이 잘리지 않는다. 병합/숨김/기본 서식/행 높이를 반영한다. Excel 앱의 픽셀 단위 스크린샷은 아니며, 테마·조건부 서식·인쇄 페이지 분할까지 재현하지 않는다. 새 집행내역의 필요한 행은 펼치고 긴 적요의 행 높이를 늘린다.

## 검증과 실제 적용 전 남은 자료

- 합성 자료로 전일 이월, 원화 만기 감소, 주요 집행/익일 계획, 총 원화 대사, XLSX 재열기, 병합 보존, 실제 PNG 생성 테스트를 수행한다.
- 실물 예시 parser 확인: KC 계좌 50개, 원화 계좌잔고 합계 **177,119,320,840**, 원화 장부합계 **178,118,834,060**. 주간계획은 10/12~10/16의 지주현금 18건. 원본을 repository에 복제하지 않는다.
- 첨부 일보는 5/27·5/28, KC/주간계획은 10월이므로 세 파일을 결합한 실제 완성본과 수작업 정답 비교는 아직 할 수 없다. **10/12 마감 일보가 있는 통합문서와 확인된 10/13 실적**으로 마지막 검증이 필요하다. 5월 예금을 10월 상태로 임의 갱신하지 않는다.
- 하나은행 공개 화면의 실제 POST 응답으로 최종 고시 매개변수(`pbldDvCd=0`), 매매기준율 열과 엔화 단위를 확인했다. 공개 HTML이 바뀌면 adapter가 중단한다. 은행의 고정 SLA API는 아니다.

## 재현용 합성 데모

```sh
node --experimental-strip-types scripts/daily-cash-demo.ts fixtures/daily-cash
```

Node 22.5 이상(테스트는 Node 24). 입력 3개와 결과 XLSX/PNG, 확인 요청 텍스트를 생성한다. 전일 현금 100,000 + 만기 원금 10,000 − 지급 1,000 = **109,000**, 익일 계획 반영 후 **107,000**이다. 오프라인 데모 환율은 합성 고정값이며 실제 하나은행 환율이 아니다. 앱에서 입력 파일을 선택해 실행하면 실제 하나은행 조회와 담당자 확인을 거친다.
